The error message tells you exactly what's wrong:

```
Got a packet bigger than 'max_allowed_packet' bytes
```

Even though you specified `--max_allowed_packet=1500M` on the **client** command line, the **server** still has its own `max_allowed_packet` setting that is too small. The client setting only affects what the client can send/receive — the server will still reject packets larger than its own configured limit.

## Fix: Increase `max_allowed_packet` on the MySQL server

### Option 1: Set it at runtime (quick test)

Connect to the running container and set it globally:

```bash
sudo docker exec -i a2bdd4db352a /usr/bin/mysql -u root -p -e "SET GLOBAL max_allowed_packet=1073741824;"
```

Then retry your import. Note: this setting will be lost if the container restarts.

### Option 2: Pass it as a command-line flag to the MySQL server (persistent for the container)

If you started the container with `docker run`, you need to restart it with the flag:

```bash
docker run ... --max-allowed-packet=1073741824 ...
```

Or if using `docker-compose`, add to your `docker-compose.yml`:

```yaml
services:
  mysql:
    image: mysql:5.7
    command: --max-allowed-packet=1073741824
```

### Option 3: Mount a custom MySQL config file (most maintainable)

Create a custom config file on your host, e.g., `/path/to/my.cnf`:

```ini
[mysqld]
max_allowed_packet=1073741824
```

Then mount it into the container:

```bash
docker run ... -v /path/to/my.cnf:/etc/mysql/conf.d/custom.cnf ...
```

Or in `docker-compose.yml`:

```yaml
services:
  mysql:
    image: mysql:5.7
    volumes:
      - /path/to/my.cnf:/etc/mysql/conf.d/custom.cnf
```

After changing the config, restart the container.

## Verify the server setting

After applying the fix, check the actual server value:

```bash
sudo docker exec -i a2bdd4db352a /usr/bin/mysql -u root -p -e "SHOW VARIABLES LIKE 'max_allowed_packet';"
```

It should show `1073741824` (1 GB) or your chosen value.

## Additional notes

- **16 GB dump**: Even with a large `max_allowed_packet`, importing a 16 GB dump can take a long time. Consider splitting the dump into smaller chunks or using `mysql` with `--compress` if network bandwidth is an issue.
- **The "connection reset by peer"** is likely a secondary symptom — the server aborted the connection due to the packet size, which caused the Docker socket read to fail.
- **Make sure you're editing the right config file**: The MySQL Docker image reads config from `/etc/mysql/conf.d/` and `/etc/mysql/mysql.conf.d/`. If you edited a file that isn't being read, your changes won't take effect.
