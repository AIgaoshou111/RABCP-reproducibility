The issue is that your Docker container's MongoDB is listening on port **27017 inside the container**, but you're mapping it to **27018 on the host** incorrectly.

## The Fix

Change your `docker-compose.yml` port mapping from:
```yaml
ports:
  - "27018:27018"
```
to:
```yaml
ports:
  - "27018:27017"
```

The format is `host_port:container_port`. MongoDB inside the container listens on 27017 (as shown in your logs: `waiting for connections on port 27017`), so you need to map host port 27018 to container port 27017.

## Accessing from RoboMongo

After fixing the port mapping and restarting with `docker-compose up`, connect RoboMongo to:
- **Address**: `localhost`
- **Port**: `27018`

This will connect to the MongoDB running in Docker, separate from your local MongoDB on port 27017.

## About Your Second Error

The error `failed to connect to server [mongo:27017]` is from your **web container** trying to connect to the MongoDB container. This is actually correct behavior - inside the Docker network, your web app should connect to `mongo:27017` (the container's internal port). 

The error occurs because:
1. Your web app is trying to connect before MongoDB is ready, OR
2. The MongoDB container isn't running properly

To fix this, ensure MongoDB is fully started before your web app tries to connect. You can add a restart policy or health check:

```yaml
version: "2"
services:
  web:
    build: .
    ports:
      - "3000:3000"
    links:
      - mongo
    depends_on:
      - mongo
  mongo:
    image: mongo
    volumes:
      - /data/mongodb/db:/data/db
    ports:
      - "27018:27017"
```

Note: `depends_on` only waits for the container to start, not for MongoDB to be ready. If you still get connection errors, you may need to add retry logic in your application or use a wrapper script that waits for MongoDB to be available.
